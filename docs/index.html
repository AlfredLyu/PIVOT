Abstract

Streaming long-video understanding is a realistic setting for always-on video assistants, where visual input arrives continuously and users may ask questions at arbitrary times. We study streaming long-video question answering (QA) under a unified temporal formulation in which multiple questions are revealed over time and may concern the past, present, or future relative to their query times. The model receives no task-type labels and must operate under strict sequential access and bounded shared memory, deciding whether each active question is already answerable or should remain open for future evidence.

To evaluate this formulation, we propose Ref2Stream (Reference-to-Stream), a general benchmark-conversion protocol that turns temporally grounded offline video QA benchmarks into streaming QA benchmarks. Instantiated on LVBench, it yields LVBench-Ref2Stream, which mixes past, present, and future questions and evaluates both answer accuracy and answer latency. We introduce PIVOT, a unified agentic framework that incrementally updates bounded memory from the observed stream and uses a planner-controlled action loop to retrieve relevant memory, analyze current evidence, reflect on candidate answers, and decide whether to answer or defer.

The Setting

An always-on assistant must answer from what it has seen so far, and know when it has not seen enough.

Unified temporal questions

Past, present, and future questions are mixed in one stream with no type labels, so the model itself must decide whether a question is answerable now or must wait.

Bounded shared memory

Frames arrive strictly in order and cannot be revisited. All questions share one fixed-budget memory that must be kept before future questions are known.

Long videos, many questions

Multiple questions arrive over hour-long videos and stay active until answered, so evidence can lie far apart in time.

LVBench-Ref2Stream Benchmark

LVBench-Ref2Stream turns LVBench, an hour-scale offline video QA benchmark, into a streaming benchmark. Each question keeps its original options and answer, and is given a query time t (when it is asked during the stream) and a ground-truth answer time g (when it first becomes answerable), based on where its visual evidence [l, r] appears:

Shaded band: sampling range for the query time t; dot: an example query. Present questions are only built for point-like references.

The benchmark contains 977 questions (452 past, 63 present, 462 future), one per source LVBench QA, so that no two variants of the same question share a stream. Questions are revealed only at their query times, without temporal-type labels, and are scored on both accuracy and answer latency.

Method

Streaming memory maintenance

For every incoming chunk, a memory manager updates a bounded, question-agnostic structured memory: a frame buffer, a scene log, a character registry, and per-question evidence notes. Budget control keeps it bounded via reservoir sampling.

Agentic question processing

For each active question, a core planner runs a short action loop: retrieve from memory, analyze the current chunk, reflect on a candidate answer, and then either answer now or defer to future chunks.
